## Native publishing boundaries

Instagram performs create-container, polls status, then publishes. Its exact payload carries one content-addressed image URL/digest, alt text, and AI-generated disclosure. Facebook uses feed or photo endpoints and GBP uses the fixed v4 local-post endpoint; their current request builders send the image URL but do not support alt/AI metadata, so the canonical provider payload omits those fields instead of implying the providers receive them. Each approved item also carries the non-secret destination account/location and exact host/version. Instagram hosts are allowlisted to `graph.instagram.com` or `graph.facebook.com`; Facebook and GBP hosts/versions are fixed. Runtime credentials/configuration must match the approved destination before request construction and again inside the guard before every provider HTTP attempt, including status reads and retries. Tokens are excluded, so credential rotation is compatible when the destination does not change; any destination change requires a new package/review. Current endpoint versions, permissions, quotas, test accounts, account ownership, and platform-review state require provider-side verification before go-live or upgrades.

The code performs all externally visible formatting before review. The approval subject is the exact canonical multi-platform provider array: it must be nonempty, every item strict-valid, and each platform unique. This complete invariant is enforced before approval creation and decision, on durable load, at publication entry, and inside the live guard. Every `PostingProvider` must await the supplied `PublicationGuard.beforeMutation()` immediately before every provider HTTP attempt—including reads, each retry/poll, and every step of a multi-request flow—or it is not an admissible implementation. The callback name is transitional; its boundary is all provider I/O. The native provider accepts only its module-issued exact-package guard, not a caller-forged/no-op object. It rechecks durable hash, decision agreement, type, status, authorization expiry, revocation, whole subject, item index/exact item, runtime target parity, and each hosted media row/live byte digest plus 5-MiB JPEG allowed-profile policy before GBP/FB requests and Instagram container creation, every status GET, and final publish. Native requests refuse redirects; request builders encode only the approved abstraction/destination, and 2xx without a provider post ID is failure.

Native posting attempts have a 30-second request timeout. fal generation attempts use 120 seconds; the intermediate download accepts only a direct allowlisted HTTPS `fal.media` URL without credentials, fragment, nonstandard port, or redirect and uses 30-second/20-MiB bounds. Runtime emits deterministic quality-90 JPEG and rejects output over 5 MiB. Google token refresh uses 10 seconds; Instagram token refresh uses 30 seconds; Slack approval/token-alert attempts use 10 seconds. Credential-bearing Google OAuth, Instagram refresh, Meta/Google diagnostics, Slack, and native provider requests refuse redirects; Instagram refresh/diagnostics also resolve only the exact configured allowlisted Meta host. The runtime state pool uses 10-second connection and query bounds. The forward migration runner has no equivalent pool-level connection/query timeout; migration 005's transaction-local lock and statement deadlines begin only after it connects and starts the migration transaction. Retry/backoff can make the complete operation longer than one attempt. The code retries network/429/5xx failures, but it does not persist an idempotency key or a provider operation ledger, so retries/crashes can require manual duplicate reconciliation. A provider result is successful only when its response includes the expected post ID; that result is captured in the brief outcome but is not later revalidated. Phase 0A does not claim provider-side exactly-once behavior.

New generated media is served from the exact `PUBLIC_BASE_URL` origin at `/media/<uuid>-<sha256>.jpg`. Before every provider HTTP attempt, the guard requires that URL/digest to name a row with immutable id/MIME/bytes/digest, recomputes the live byte digest, and revalidates the stored bytes as a no-more-than-5-MiB JPEG in one of the four allowed exact feed profiles. The UUID-only media route stays readable for earlier published links. Migration 005 prevents those content/id changes and every media deletion, so future retention requires a reviewed schema change rather than normal cleanup.

The worker scopes token acquisition to the intended platform. Its startup/12-hour Instagram token tick exists only when Instagram is in `ACTIVE_PLATFORMS`; the default Instagram-login path persists/refreshes a PostgreSQL-backed token, while the alternate Facebook-login host remains environment-managed. After approval it invokes the current-token helper only if the immutable approved array contains Instagram, and attempts Google OAuth refresh only if that array contains GBP. Environment credentials are still loaded into the provider credential object, and default-path Instagram token state remains plaintext; this gating prevents unrelated refresh calls, not credential isolation or encryption.

## Slack approval boundary

The worker posts a URL containing the one-time decision token to a Slack incoming webhook. Every environment that runs worker approval delivery must configure an exact HTTPS `hooks.slack.com/services/...` webhook; blank is valid only when that flow is not run, such as a direct offline `createApproval` test. Production additionally requires a public root HTTPS review origin. Each model-authored summary line is bounded, sanitized, and then code-delimited so controls, mrkdwn, links/bare domains, mentions, and backticks remain inert; the generated URL is labeled as the authoritative exact-payload review and is the message's sole active link. Best-effort escalation messages similarly bound and neutralize model/trigger-authored goal, reason, and run ID. Notification requests refuse redirects and retries bound each attempt to 10 seconds. If approval delivery cannot be confirmed, bounded revocation attempts must confirm the row is revoked; failure to confirm surfaces a composite notification/revocation error for reconciliation and returns no handle. The token defaults to a 24-hour lifetime and only its SHA-256 is stored; the independently expiring publication authorization can be revoked in code. No email fallback or authenticated reviewer identity exists. Configure a private channel, restrict webhook owners, minimize link retention, and treat message history/browser/proxy logs as bearer-token exposure paths. An expired, revoked, or already-used link cannot create another decision.

## Arcade boundary

Arcade consumes `/console/manifest`, `/console/state`, and `/console/stream`. Configure a nonempty matching `CONSOLE_TOKEN` in both repositories and send it as `Authorization: Bearer` or `x-console-token`. Query credentials and wildcard CORS are no longer accepted. All three console routes share the same transitional gate and process-local 120/minute limit; confirm the consumer supports that contract before rollout.
