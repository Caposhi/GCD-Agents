  **Qualification must govern the proposition, which is a structural test rather than a vocabulary one.** A subordinator — *whether*, *if*, *after*, *once*, *when*, *whenever*, *before*, *until*, *unless*, *should* — counts only when it introduces the very clause the predicate heads: everything between the subordinator and the predicate must be that clause's own subject, matched against a **whitelist**, so anything unexpected in that gap leaves the assertion bare and the rule fails closed. Two things therefore qualify nothing. A qualifier merely co-occurring in the clause (*verify*, *observed*, *establish*, even *UNKNOWN*) does not — the defect in the first version of this check. Neither does an unrelated introductory clause placed in front of the assertion (*"Before we verify, migration 007 is applied."*, *"If this note is read, …"*, *"Once more, …"*) — the defect in the second, which accepted any subordinator that merely **preceded** the predicate. Punctuation alone is not a proposition boundary: a bare comma can close an introductory clause, while a **balanced** comma pair or parenthesis is treated as an interruption and stepped over — either because its interior carries no clausal verb at all, or because it is opened by a subordinator and is therefore a **subordinate aside**. That second case is what preserves an outer finite frame across an aside with a verb of its own (*"Migration 007 has, after the report was signed, been applied."* is a perfect assertion and is refused); the aside's `was` belongs to the aside, and the aside's own subordinator governs nothing outside it. **Three mechanics make that work on natural wording, and they are stated exactly.** Openers are matched over **one, two or three leading tokens**, so a phrase opener (*even though*, *now that*, *provided that*, *as long as*) is recognised as well as a single word. Comma pairing prefers the **outermost** qualifying opener rather than the nearest comma, and a shared endpoint is resolved to that outermost start, so two consecutive asides and a nested one (*"because the report, once reviewed, was signed"*) are stepped over as a single span instead of leaving overlapping pairs a leftward walk falls back inside. **Parentheses are paired by depth**, with a stack, so a nested aside (*"has (according to the operator (per the audit)) been applied"*) yields nested spans and no closing parenthesis is left dangling; matching an opener to the first later `)` recorded an *inner* close as the outer one and left the real outer close unmatched, which the leftward walk then read as a proposition boundary. And because no opener list can be complete, **finite-frame recovery fails closed and depends on no list at all**: `been`/`be`/`being applied` is not a proposition on its own, so when the walk meets a comma it does not recognise while holding only that non-finite frame, it crosses the aside and keeps looking for the finite auxiliary rather than reading the participle as non-assertive. An unlisted opener (*"seeing as the report was signed"*) is therefore still refused. An unmatched **closing** parenthesis is handled differently and deliberately: it is **not** recovered through at all. Recovery through an unmatched `)` was itself a fail-open — one stray close bought a bypass, because the walk skipped it, halted at the intervening noun and never reached the outer auxiliary — so that behaviour has been **removed**. An unmatched `)` is malformed prose, and a depth scan of the normalized comment prose fails `CC5` **structurally** on any `)` at depth zero, **before** any application predicate is classified, so no recovery heuristic is consulted about it and no authorized `UNKNOWN` sentence elsewhere in the prose can mask a malformed categorical one. What is **not** claimed: an aside is only recognised as *subordinate* when its opener is on the list, so a governed proposition wrapped around an unlisted aside may still be refused — the failure direction is closed, not open. Nor is an unmatched **opening** parenthesis with no punctuation between it and the participle covered: the walk stops at the intervening noun before reaching it. That is malformed input rather than a supported authoritative-comment form, it appears in neither file, and it is stated here rather than left implied.

  **Every proposition is judged on its own, and an authorized one authorizes nothing but itself.** `CC5` enumerates **every** application-state predicate in a clause rather than only the earliest, and binds all three judgements — where the predicate starts, which exemptions apply, which subordinator governs it — to that one predicate's **own local frame**, the text between the previous predicate and this one. A subordinator that already governs an earlier predicate cannot reach across it. A clause is clean only when **every** predicate it carries is exempt or governed, so a genuinely authorized proposition can no longer carry a categorical sibling along with it (*"Whether migration 007 is applied is `UNKNOWN` **and migration 007 is applied**."*) — the defect in the third version, which stopped at the first predicate and allowed the whole clause once that one was governed. This is deliberately **not** a split on `and`/`but`: those conjunctions occur inside governed propositions too, so the association is structural. What coordination is handled is stated narrowly and no wider: a coordinator is stepped over **inside** one governed proposition — within the governor's reach when the token beside it is one the reach already admits (*"whether or not … has been applied"*, *"whether … has or has not been applied"*), and between two predicates only when nothing but that coordinator, an auxiliary, a negator or an adverb separates them (*"whether … was applied or ran"*). A **serial comma** counts as a joint too (*"whether … was applied, ran, or was re-applied"*), and a validated interruption span inside the gap is skipped rather than ending it (*"was applied or (after read-only verification) ran"*). A coordinator that introduces a **new subject**, an adversative such as *but*, a bare imperative *do*, or any other intervening word makes the next predicate a separate assertion, judged on its own and refused if categorical. Separately, bare *do*/*don't* with no subject of its own heads an **instruction**, not a claim (*"Unless migration 007 is applied, do not run the rollback."* is allowed), while *does* and *did* stay declarative and emphatic (*did run*, *did not run* are refused). No general handling of coordination is claimed beyond those forms. Two supporting details make it hold: the auxiliary chosen for a predicate is the one **nearest** the verb, never the leftmost, which would otherwise belong to the preceding proposition; and a bare finite past (*ran*) is its own predicate and looks for no auxiliary at all. `CC5` further requires both files to state the live state is `UNKNOWN` in either direction, to keep the 2026-08-28 reading dated, and to require separate authorization.

**A payload-escaping defect in the harness was found and corrected in the same round.** One hundred and fifty-two mutation payloads (`M106`–`M107` and `M118`–`M267`) wrote a **literal backslash and `n`** into the SQL file instead of a newline, because the source carried `"\\n"` rather than `"\n"`. ## GitHub CI behavior

`.github/workflows/ci.yml` runs on pull requests to `main`, pushes to `main`, and manual diagnostic dispatch. The Node 22 quality job runs the locked install, build/typecheck, `npm run test:offline` (currently the nine canonical offline self-test commands listed above), simulated dry run, controller fixtures, repository checks, whole-tree whitespace check, and production dependency audit; it never invokes `dryrun:live`. A two-version disposable matrix reuses `test:postgres`, then migrates a dedicated database and runs `test:http-e2e` on PostgreSQL 16 for established compatibility and PostgreSQL 18 for production parity. AgentShield 1.4.0 is a separate required job: a nonzero scan exit fails CI, and its JSON report upload uses `if: always()` so evidence is retained after a scan failure. Workflow validation downloads actionlint 1.7.12 from its pinned release, verifies its archive checksum, runs it against every workflow, and parses checked-in YAML.

CI has no production secrets. Its only database uses loopback credentials inside the disposable runner service, and the HTTP self-test denies outbound fetch. The production deployment workflow triggers only from a successful push-originated `CI` run on `main`; manual CI dispatch cannot deploy. See [Deployment control](DEPLOYMENT.md).
