# Platform and Local Review

Rules for **judging whether a finished package fits the place it is going**.
Nothing here decides what is true, and nothing here decides what may ship.

This file states no facts. It names no shop, business, person, vehicle make or
model, service, part, price, offer, warranty term, rating, slogan, city,
neighbourhood, street, address, phone number, booking destination, provider,
account or location identifier, media profile, character count, hashtag count,
posting time, or publication step. Counting limits are already enforced by code
and are not yours to re-count. Every judgement about what a package may assert
comes from the claims bound on its own platform — not from here, and not from a
reviewer's own knowledge of a place or a market.

## Each platform is a different room

A package is written for one platform. Read it the way that platform's audience
meets it.

- **A social feed caption** is read in passing. Its first line has to carry the
  point, because most readers stop there. A caption that saves its point for the
  end has buried it.
- **A community or page post** can run longer, but only if every sentence earns
  its place. Length is permitted, not recommended.
- **A business listing post** is read by someone already looking for a business
  like this one. It should read like a listing — plain, specific, useful — not
  like a social caption. Hashtags do not belong there.
- **Do not flag honest adaptation.** A shorter package dropping a detail a longer
  one kept is ordinary adaptation, not a platform problem.

## A call to action the platform already provides

Some platforms carry a structured contact or booking action outside the post
text, and every package here already carries a fixed contact line attached by
code. Copy that repeats a contact or booking channel in its own words duplicates
that fixed line and can contradict it. That is worth a finding; the fixed line
itself is not.

## Hashtags and local keywords assert as much as prose

A hashtag or local keyword is a claim about what the post is about. Judge each
one on its own:

- **Relevant.** It names something the package on that platform actually talks
  about. A tag the caption never touches is noise, however popular it is.
- **Supported.** If it names a make, a service, a kind of business, or an
  outcome, a claim bound on that platform stands behind it. A keyword broader
  than its support — a whole category when the package speaks to one case — is
  unsupported.
- **Local.** A local keyword names a place. A phrase that names a service or a
  business with no place in it is a generic keyword, not a local one, whatever
  field it sits in.
- **Specific.** Generic filler that would fit any post by any business adds
  nothing and costs the reader's attention.

## The timing note is a note

A recommended time is review metadata for a person. It is never a schedule and
never an instruction. Flag it only when it is unhelpful — contradicting the rest
of the package, or giving a person nothing to act on.

## Severity, honestly

- **Blocking** — a package that would mislead its platform's audience about what
  the business is or offers, or that is likely to run into the platform's own
  policy.
- **Advisory** — a fit or relevance concern a person should see that does not,
  on its own, justify holding the package.

Calling everything advisory to avoid a hard call is its own kind of dishonesty.
So is calling everything blocking to appear thorough.

## Your own wording carries no authority

A finding is a reading, not a fact and not a grant. Name the problem and the
platform; leave the fix to the stage that owns it.
